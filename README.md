# To-Do Web App

The same to-do list logic as the console version, now packaged as an Eclipse
Dynamic Web Project (Maven + WTP) so it matches the folder layout of a
typical Java EE / servlet tutorial project.

## Structure

```
todo-webapp/
├── .project                 # Eclipse project descriptor (Java + Dynamic Web facets)
├── .classpath                # Eclipse build path (JRE, Maven, Tomcat container)
├── .settings/                 # Eclipse/WTP facet + compiler settings
├── pom.xml                   # Maven build, packaging = war
├── target/m2e-wtp/...        # auto-generated by m2e-wtp on import/build
└── src/
    ├── main/java/com/todoapp/
    │   ├── Task.java          # to-do item (unchanged from console app)
    │   ├── TaskManager.java   # add/list/mark-done/delete logic
    │   └── TodoServlet.java   # HTTP front end, routes GET/POST on /todo
    └── main/webapp/
        ├── WEB-INF/web.xml    # welcome-file only; routing is via @WebServlet
        └── index.jsp          # renders the list + add/done/delete forms
```

## Import into Eclipse

File → Import → Existing Maven Projects → select this folder.
Eclipse/m2e-wtp will regenerate `target/m2e-wtp` and recognise it as a
Dynamic Web Project automatically because of the `.project` / `.settings` files.

## Run it (command line, without Eclipse)

Needs a servlet container. Easiest is Tomcat 10+ (Jakarta EE namespace, matches
the `jakarta.servlet-api` dependency in pom.xml):

```bash
mvn clean package
cp target/todo-webapp.war $CATALINA_HOME/webapps/
$CATALINA_HOME/bin/catalina.sh run
```

Then open: http://localhost:8080/todo-webapp/todo

## Notes

- State is in-memory only (a single `TaskManager` instance held by the
  servlet) — it resets whenever the app is redeployed or the server restarts.
- If you deploy under a different context path, hit `/<context>/todo` instead.
